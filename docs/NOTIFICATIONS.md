# 알림(푸시) 설계

> **목적:** "오후 7시에 시작 알림, 오후 9시에 잘 끝났냐는 알림"을 어떻게 만들지 정리한 문서.
> **상태:** **단계 0(테스트 관문) 구현됨** — 설치·권한·테스트 알림까지. 서버 발송(1~3단계)은 아직.
> **작성:** 2026-07-22

---

## 0. 쉽게 말하면 (기술 배경 없이 읽는 절)

### 문제는 딱 하나다

**"앱이 꺼져 있는데 어떻게 밤 7시에 울리지?"**

폰 안의 앱은 꺼지면 아무것도 못 한다. 그러니 **그 시각에 깨어 있는 누군가**가 앱 바깥에 있어야 한다. 알림 기능은 결국 이 하나를 만드는 일이다.

### 용어 세 개

- **서버** = 항상 켜져 있는 남의 컴퓨터. 특별한 물건이 아니라 "안 꺼지는 컴퓨터"라는 역할 이름이다
- **클라우드** = 그 컴퓨터를 사서 두는 게 아니라 **빌려 쓰는 방식**. 서버가 자동차라면 클라우드는 렌터카다
- **Supabase** = 우리가 쓰는 렌터카 회사. 앱 뒷단에 필요한 것(정보를 담는 표 + 구글 로그인 + 서버에서 도는 작은 프로그램 + 정해진 시각 자동 실행)이 한 세트로 들어 있다

### 서버도 DB도 이미 있다 — 새로 만드는 게 아니다

Future Me는 **처음부터 Supabase 위에 올라가 있다.** 구글 로그인, 프로필·할 일이 다른 기기에서도 보이는 것 전부 Supabase가 하는 일이고, 설계도는 [supabase/schema.sql](../supabase/schema.sql)에 있다. 지금 표가 이미 4개다 — `futureme_profiles`, `futureme_chats`, `futureme_settings`, `futureme_goal_data`.

그래서 이번에 하는 일은 **이미 빌려 쓰는 것 위에 세 가지를 얹는 것**이 전부다.

1. **표 2개 추가** — 알림 보낼 주소록, 보낸 기록
2. **작은 프로그램 1개** — "지금 7시네? 7시 일정 있는 사람 찾아서 보내"
3. **자동 실행 켜기** — 그 프로그램이 매분 돌게

여기에 앱 쪽 작업(홈 화면에 설치 가능하게 + "알림 받기" 버튼)이 붙는다. 새로 사는 것도, 새 개념을 배우는 것도 없다.

### 우체국 비유

| 만들 것 | 쉽게 말하면 |
| --- | --- |
| PWA 껍데기 | 앱을 **홈 화면에 설치**할 수 있게 만드는 것 (아이폰은 이게 있어야 알림을 준다) |
| 서비스 워커 | 앱이 꺼져 있어도 알림을 받아 띄우는 **작은 수신기** |
| 구독 정보 | 형 폰의 **배송 주소**. "알림 받기"를 누르면 브라우저가 발급해준다 |
| Supabase | **주소록 + 시계**. 매분 "지금 7시네? 7시 일정 있는 사람?" 확인 |
| VAPID 키 | 우리 앱의 **신분증**. "이 알림은 Future Me가 보낸 게 맞다"는 증명 |

### 실제로 도는 모습 (7/23 러닝 19:00~20:00)

1. **미리 한 번:** 앱에서 "알림 받기" 누름 → 폰이 배송 주소 발급 → 서버 주소록에 저장
2. **일정 저장:** 러닝 일정이 클라우드로 올라감 (서버가 알아야 하니까)
3. **18:59:** 서버가 확인 → 아직 아님
4. **19:00:** 서버가 확인 → "이 사람 19:00 러닝 있네" → 주소로 발송
5. 🔔 *"이제 시작할 시간이야 — 러닝"* → 누르면 앱이 열림
6. **20:00:** 🔔 *"잘 끝났어? 기록해두자"*

### 사용자가 하는 건 두 가지, 그것도 한 번뿐

1. (아이폰이면) 사파리에서 **공유 → 홈 화면에 추가**
2. 앱에서 **"알림 받기"** 누르고 권한 **허용**

## 1. 무엇을 만들려는가

할 일에 시간이 붙어 있으면 (`timeStart` / `timeEnd` — 3bb8f04에서 종윤이 추가), 그 시각에 폰이 울린다.

| 시각 | 알림 | 누르면 |
| --- | --- | --- |
| 시작 시간 (예: 19:00) | "이제 시작할 시간이야 — 러닝 30분" | 앱의 홈(오늘 할 일)이 열린다 |
| 끝 시간 (예: 21:00) | "잘 끝났어? 기록해두자" | 그 할 일 체크 또는 하루 마감으로 |

**이게 왜 이 앱에 맞나:** 미래의 나가 "증거를 가진 존재"가 되려면 오늘 한 걸음이 실제로 일어나야 한다. 다만 잔소리가 되면 안 되므로 알림 문구·빈도는 §5의 원칙을 따른다.

---

## 2. 먼저 정리 — Gemma 3는 이 문제와 무관하다

찾아본 것 중에 섞여 있어서 명확히 해둔다.

- **Gemma 3 / LLM** = "무슨 말을 할지" 만드는 것
- **알림** = "정해진 시각에 사용자 기기를 깨우는" **배달** 문제

알림에 LLM은 필요 없다. 나중에 알림 문구를 미래의 나 말투로 생성하고 싶을 수는 있지만, 그건 이 기능이 돌아간 **다음** 얘기고, 서버에서 매번 LLM을 호출하면 비용·지연·실패 지점만 늘어난다. **v1은 템플릿 문구로 간다.**

## 3. 기술적으로 가능한가 — 가능하다. 방법은 사실상 하나다

웹앱을 유지하는 한 선택지는 **PWA + 웹 푸시(Web Push) + 서버 스케줄러** 하나다. 나머지는 다음 이유로 탈락:

| 방법 | 판정 | 이유 |
| --- | --- | --- |
| 앱이 열려 있을 때 `setTimeout` + `Notification` | ❌ | 탭을 닫으면 끝. 알림의 의미가 없다 |
| Notification Triggers (기기 안에서 시각 예약) | ❌ | 웹 표준으로 안 정착했다. 기대면 안 된다 |
| **PWA + 웹 푸시 + 서버 크론** | ✅ | 앱이 꺼져 있어도 온다. 아래가 이 방식이다 |
| 네이티브 앱(React Native 등) | 보류 | 알림은 제일 확실하지만 앱스토어·심사·별도 코드베이스. 지금 규모엔 과함 |

### 3-1. 도는 방식

```
[기기]                          [Supabase]                        [기기]
알림 허용 → 구독 정보 저장  →   push_subscriptions 테이블
할 일 저장 → 클라우드 동기화 →  futureme_goal_data
                                      ↓
                            pg_cron: 매분 실행
                                      ↓
                     "지금 시각 == 시작/끝 시간"인 할 일 찾기
                                      ↓
                        Edge Function: 웹 푸시 발송  →  🔔 알림
```

### 3-2. 필요한 것 (지금 없는 것)

1. **PWA 껍데기** — `manifest.json`, 서비스 워커. 지금 저장소에 둘 다 없다
2. **알림 권한 UI** — "알림 받기" 버튼 (사용자 조작에서만 권한 요청 가능)
3. **구독 저장 테이블** — 새 Supabase 테이블 `futureme_push_subscriptions`
   (`user_id`, 브라우저가 준 구독 JSON, **기기 타임존**, 켬/끔) + 발송 기록 `futureme_push_sent`
4. **스케줄러** — Supabase Edge Function + pg_cron (매분)
5. **VAPID 키 한 쌍** — 웹 푸시 신원 확인용. 한 번 만들어 환경변수로

## 4. 반드시 알아야 할 제약 3가지

### 4-1. 아이폰은 "홈 화면에 추가"해야만 알림이 온다

- 사파리 **탭으로 열어둔 상태에서는 절대 안 온다.** 홈 화면에 설치한 PWA만 가능 (iOS 16.4+, 2023년 3월부터)
- **EU 지역은 제외** (iOS 17.4+ 정책)
- → 온보딩이나 알림 설정 화면에 **"홈 화면에 추가하는 법" 안내가 필수**다. 이걸 안 하면 아이폰 사용자는 이유도 모른 채 알림을 못 받는다
- 안드로이드·PC 크롬은 설치 없이도 됨

### 4-2. 로그인이 사실상 필수가 된다

지금 할 일은 **기기 안(localStorage)에만** 있다. 서버가 모르면 시간 맞춰 쏠 수가 없다.

- 로그인 + 클라우드 동기화한 사람만 알림을 받는다
- 즉 **"알림 = 로그인 기능"** 이 된다. 로그인 안 한 사람에겐 알림 설정 화면에서 그 이유를 말해줘야 한다

### 4-3. 정확도는 ±1분

매분 도는 크론이라 19:00:00 정각이 아니라 19:00~19:01 사이에 온다. 이 용도엔 충분하다고 본다.

### 4-4. 타임존 — 서버가 풀어야 할 진짜 문제

`timeStart: "19:00"` 에는 **타임존이 없다.** 사용자 기기의 로컬 시각이다. 서버는 "지금 이 사람에게 19:00인가"를 알아야 하므로:

- 구독을 저장할 때 **기기 타임존을 같이 저장한다** (`Intl.DateTimeFormat().resolvedOptions().timeZone` → 예: `Asia/Seoul`)
- 크론은 매분 돌면서, 각 사용자의 타임존 기준 현재 `HH:mm`을 구해 할 일과 맞춰본다
- 해외에 나가면 기기 타임존이 바뀌므로, 앱을 열 때마다 타임존을 갱신해둔다

### 4-5. 중복 발송 방지

크론이 매분 돌기 때문에, 같은 할 일에 대해 두 번 쏘지 않도록 **보낸 기록이 필요하다.**

- 제안: `futureme_push_sent` 테이블에 `(user_id, todo_id, kind: 'start'|'end', fired_on: date)` 를 유니크 키로 넣고, insert가 성공할 때만 발송
- 이러면 크론이 겹쳐 돌거나 재시도해도 한 번만 간다

## 5. 알림 원칙 (PRODUCT_PRINCIPLES와의 정합)

로드맵 원칙 1이 "미래의 나가 비서·알림봇·잔소리꾼이 되는 순간 실패"다. 알림은 그 경계에 가장 가까운 기능이라 선을 미리 긋는다.

- **사용자가 시간을 적은 할 일에만** 울린다. 앱이 알아서 시간을 정해 울리지 않는다
- **하루 총량 상한**을 둔다 (예: 6개). 넘으면 안 보낸다
- **못 지킨 걸 다시 찌르지 않는다.** 재알림·"아직 안 했네?" 없음
- **끄기 쉬워야 한다.** 할 일별 / 전체 스위치
- 문구는 담담하게. 느낌표·재촉 표현 금지

## 6. 종윤과 정할 것 (5개)

1. **스케줄러를 어디에 둘까** — 제안: **Supabase**(pg_cron + Edge Function). Vercel 크론은 무료 플랜이 **하루 1회 제한**이라 이 용도로 못 쓴다
2. **FCM(Firebase)을 쓸까** — 제안: **안 쓴다.** 웹 푸시(VAPID)만으로 충분하고 FCM은 의존성만 늘어난다. FCM 자체는 무료지만 이득이 없다. (나중에 네이티브 앱으로 가면 그때 다시)
3. **로그인 필수화를 받아들일까** — 알림을 켜려면 로그인해야 한다. 이걸 온보딩에서 어떻게 안내할지
4. **아이폰 설치 안내를 어디에 둘까** — 알림 설정 화면 안? 별도 안내 화면?
5. **v1 범위** — 시작·끝 둘 다? 아니면 시작 알림만 먼저?

## 6-1. 진행 상황 (2026-07-23)

### ✅ 단계 0 통과 — 지웅님 아이폰에서 확인

홈 화면 설치 → 알림 권한 허용 → 테스트 알림이 **실제로 떴다.** 설정 화면의 진단 4줄이 모두 초록:
설치됨 / 권한 granted / 서비스 워커 / PushManager 있음.

여기서 막혔으면 서버를 만들어도 소용없었을 부분이라, 이게 관문이었다.

**같이 확인된 사실:** 테스트 알림은 **앱이 열려 있는 동안에만** 뜬다. 5초 타이머가 앱 안에서 돌기
때문에 앱을 닫으면 iOS가 코드를 재우고 타이머도 멈춘다. → 이 문서의 전제("앱이 꺼져 있어도
깨워줄 존재가 밖에 필요하다")가 실물로 확인된 셈이다.

### ⬜ 다음: 1단계를 둘로 쪼갠다

"서버 알림 지원 ●"은 **브라우저에 PushManager가 있다**는 뜻일 뿐, **실제로 구독(배송 주소)이
발급되는지**는 아직 확인 안 됐다. 아이폰에서 여기서 막히면 또 멈춘다. 그래서:

| | 내용 | 확인 방법 |
| --- | --- | --- |
| **1-a** | `pushManager.subscribe()` 로 **주소 발급만** 시도하고 성공/실패를 화면에 표시 | 폰에서 버튼 한 번 — **두 번째 관문** |
| 1-b | 성공하면 Supabase 테이블(`futureme_push_subscriptions`) 만들고 저장 | — |
| 2 | 서버 스케줄러 (pg_cron + Edge Function) | 앱 꺼둔 채로 알림 오는지 |

1-a에 VAPID 키 한 쌍이 필요하다(공개키만 앱에 들어간다). 30분이면 만들어 확인할 수 있다.

### 배포 흐름 (2026-07-23부터)

저장소가 **public**으로 바뀌어서 Vercel의 커밋 작성자 검사가 사라졌다. 이제 지웅님이 PR을
만들고 **직접 병합**할 수 있고, 병합되면 Vercel이 자동 배포한다. 종윤님을 거칠 필요 없다.

## 7. 비용과 일정

### 비용: 0원

| 항목 | 요금 | 근거 |
| --- | --- | --- |
| Supabase | 무료 | Edge Function 월 50만 회 무료. 매분 크론 = 월 43,200회 |
| 웹 푸시 발송 | 무료 | 브라우저 표준. 발송 자체에 요금 없음 |
| Vercel | 무료 | 정적 호스팅 그대로 (크론은 안 씀) |
| FCM (쓸 경우) | 무료 | 발송 무제한 무료. 다만 §6-2대로 안 쓰는 걸 제안 |

주의: Supabase 무료 프로젝트는 **7일간 요청이 없으면 일시정지**되는데, 매분 크론이 도니까 해당 없음.

### 일정: 약 3일

| 단계 | 내용 | 시간 |
| --- | --- | --- |
| 0 | **테스트 관문** — PWA 껍데기 + 알림 권한 + "테스트 알림 보내기" 버튼 | 0.5일 |
| 1 | 구독 저장 (테이블 + 저장/해지) | 0.5일 |
| 2 | 스케줄러 (Edge Function + pg_cron + 중복 발송 방지) | 1일 |
| 3 | 알림 눌렀을 때 흐름, 끄기 스위치, 하루 상한 | 1일 |

**단계 0을 먼저 하고 멈추자.** 지웅 폰(아이폰)에서 실제로 알림이 뜨는지 확인하는 게 관문이다. 여기서 막히면(설치 안내, 권한, 지역 제한) 나머지는 지어봐야 의미가 없다. 반나절이면 답이 나온다.
